# Заметки

SPA-приложение для заметок со списками задач: Nuxt 4, Composition API,
TypeScript в строгом режиме, Pinia, собственная вёрстка на SCSS.

История изменений (undo/redo) и синхронизация с `localStorage` написаны вручную,
без готовых библиотек.

## Запуск

### Docker

```bash
docker compose up --build
```

Приложение будет доступно на <http://localhost:8080>.

Собирается статика (`nuxt generate`) и раздаётся nginx; Node в рантайме не
участвует. Итоговый образ не содержит ни исходников, ни зависимостей сборки.

### Локально

Нужен Node 20.19+ или 22+ и pnpm (`corepack enable`).

```bash
pnpm install
pnpm dev
```

| Команда              | Что делает                            |
| -------------------- | ------------------------------------- |
| `pnpm dev`           | Дев-сервер на <http://localhost:3000> |
| `pnpm generate`      | Сборка статики в `.output/public`     |
| `pnpm test`          | Unit-тесты (Vitest)                   |
| `pnpm lint`          | ESLint                                |
| `pnpm typecheck`     | Проверка типов (`vue-tsc`)            |

Пакетный менеджер — pnpm: npm 10.9 не может разрешить дерево зависимостей
Nuxt 4 и падает с `Cannot read properties of null (reading 'edgesOut')`.

## Устройство

```
app/
  core/            чистая логика без Vue — тестируется без монтирования
    types.ts         Note, TodoItem
    commands.ts      команды изменения заметки: apply / revert
    history.ts       стек undo/redo с лимитом
    note.ts          операции над заметкой: копия, нормализация, превью
    persistence.ts   чтение и запись localStorage, версия схемы, миграции
  stores/
    notes.ts       Pinia: список заметок и запись в хранилище
  composables/
    useNoteEditor.ts  сессия редактирования: черновик + история
    useUndoRedo.ts    глобальные Ctrl+Z / Shift+Ctrl+Z
  components/
    ui/            переиспользуемые примитивы: кнопка, поле, чекбокс, модалка
    NoteCard.vue      карточка в списке
    TodoEditorItem.vue строка пункта в редакторе
  pages/
    index.vue         список заметок
    notes/[id].vue    создание и изменение заметки
  plugins/
    persistence.client.ts  подъём состояния, событие storage, запись при уходе
```

Слой `core/` не импортирует ни Vue, ни Nuxt: вся семантика истории и хранилища
покрыта обычными unit-тестами, компонентные тесты не требуются.

### История изменений

Шаг истории — это **команда** с минимальной дельтой, а не снимок заметки:

```ts
type Command =
  | { type: 'title.set', prev: string, next: string }
  | { type: 'todo.add', index: number, item: TodoItem }
  | { type: 'todo.remove', index: number, item: TodoItem }
  | { type: 'todo.text', id: Id, prev: string, next: string }
  | { type: 'todo.toggle', id: Id, prev: boolean, next: boolean }
```

`apply` и `revert` — точные инверсии друг друга, это проверяется тестом на
случайных сценариях. Пятьдесят шагов истории весят меньше одной копии заметки —
на это тоже есть тест.

Правила фиксации:

- непрерывный ввод текста в одно поле — **одна** запись: она закрывается по
  паузе в 600 мс, по потере фокуса и принудительно перед любым другим
  действием, undo/redo и сохранением;
- отметка чекбокса, добавление и удаление пункта — отдельные атомарные записи;
- новое изменение после undo очищает redo-ветку;
- лимит — 50 шагов, самые старые вытесняются;
- история живёт в рамках сессии редактирования: «сохранить», «отменить
  редактирование» и восстановление черновика начинают её заново.

### Хранилище

```
notes:v1        { version: 1, notes: [...] }
notes:draft:v1  { version: 1, noteId, note, savedAt }
```

Запись отложенная: не на каждое изменение, а через 400 мс после последней
правки. Досрочная запись происходит по `visibilitychange` и `pagehide`.

Всё, что прочитано из хранилища, считается недоверенным: битый JSON, мусорные
записи и неизвестная версия схемы приводят к пустому состоянию, а не к белому
экрану. Функция `migrate()` разбирает версии явным `switch`.

## Принятые решения

Места, где ТЗ оставляет выбор или где решение может выглядеть неожиданно.

**SSR отключён.** Всё состояние живёт в `localStorage`, которого нет на сервере.
При включённом SSR каждый экран пришлось бы прятать в `<ClientOnly>` ради борьбы
с рассинхроном гидрации — это не то приложение, которое описано в задании.

**Ctrl+Z перехватывается всегда, включая текстовые поля.** Нативный undo
браузера подавляется через `preventDefault`. Иначе браузер откатывал бы
содержимое поля, не сообщая об этом приложению, и два состояния разъезжались бы.
Цена: шагом отмены становится правка поля целиком, а не отдельный символ. Код
клавиши проверяется через `event.code`, поэтому сочетание работает и в русской
раскладке.

**Создание заметки живёт на той же странице, что и редактирование** (`/notes/new`),
а в стор заметка попадает только по «Сохранить». Так отмена не оставляет в списке
пустых заметок. Страниц по-прежнему две, как требует ТЗ.

**Пустое название допустимо**, в списке такая заметка показывается как «Без
названия»: заметка может быть просто чек-листом. **Пустые пункты отбрасываются
при сохранении** — пустой текст пункта это незавершённый ввод, а не данные.
Ничего не блокируется и не подсвечивается ошибкой.

**Удаление в соседней вкладке не ломает открытый редактор.** Страница переходит
в режим «сироты» и предлагает сохранить правки как новую заметку либо вернуться
к списку. Список на главной обновляется живьём по событию `storage`.

**Досрочная запись по `visibilitychange` и `pagehide`, а не по `beforeunload`.**
На мобильных браузерах `beforeunload` не гарантирован.

**Escape в окне восстановления черновика означает «отбросить»** — это отказ от
предложенного действия. Восстановление черновика доступно только явной кнопкой.

**«Отменить редактирование» всегда спрашивает подтверждение**, даже если правок
не было: ТЗ требует подтверждения без оговорок. Текст сообщения меняется в
зависимости от того, есть ли несохранённые изменения.

**Кнопка «Удалить» скрыта на странице создания** — удалять ещё нечего.

## Обработанные edge-cases

- Прямой переход по адресу несуществующей заметки — отдельный экран «Заметка не
  найдена» с возвратом к списку.
- Пустое название заметки и пустой текст пункта — см. выше.
- Удаление заметки, открытой на редактирование в другой вкладке.
- Повреждённые или чужие по версии данные в хранилище.
- Переполнение квоты хранилища не ломает редактирование.
- Удаление пункта во время набора его текста.
- Отметка чекбокса во время набора текста не обгоняет текст в истории.

## Доступность

- Модальные окна: `role="dialog"`, `aria-modal`, ловушка фокуса на Tab и
  Shift+Tab, закрытие по Escape, возврат фокуса на элемент, который открыл окно,
  блокировка прокрутки страницы.
- Все подтверждения — модальные окна, `alert` и `confirm` не используются.
- Видимое кольцо фокуса (`:focus-visible`), учитывается `prefers-reduced-motion`.
- Чекбоксы в карточке на главной — рисунок, а не `disabled`-поле: там нельзя
  отмечать пункты, и такие элементы не попадают в обход с клавиатуры.
- Тёмная тема через `prefers-color-scheme`.
